# 서비스 관리

## 설치와 업데이트
Windows x64 설치 파일은 `ChunggwakMohae-Setup-2.0.0.exe`입니다. 기존 공개 `v1.1.0` 릴리스는 이전 이름의 `ChunggwakPT-Setup-1.1.0.exe`이며, 2.0.0 파일과 구분하세요. Node와 AI 실행 파일이 포함되어 별도 개발 도구 설치가 필요하지 않습니다. 설치 대상은 현재 Windows 사용자의 LocalAppData 아래이며 관리자 권한은 필요하지 않습니다. 이름 변경 후에도 설치 ID와 데이터 경로는 유지됩니다. 브라우저 창을 닫아도 백그라운드 프로그램은 남습니다.

업데이트 전 시작 메뉴에서 충곽 뭐해를 종료하세요. 같은 위치에 새 설치 파일을 실행하면 프로그램 파일을 교체하고 `data`는 유지합니다. 제거할 때도 개인 데이터는 남깁니다. 사용자 데이터 전체를 없애려면 먼저 백업하고 프로그램 종료 후 설치 폴더의 `data`를 직접 관리하세요.

## 계정과 AI
프로그램 사용자 계정과 ChatGPT 로그인은 별도입니다. 사용자마다 AI 개발실에서 본인 ChatGPT 계정을 연결합니다. AI는 전역 Codex 로그인이나 운영자의 API 키를 가져오지 않습니다. 각 프로필의 인증 정보는 `data/ai/<사용자 ID>/auth`에 Codex가 저장합니다. 브라우저에는 연결 이메일·플랜·진행 상태만 반환하며 토큰을 반환하지 않습니다.

이는 로컬 프로그램의 사용자 분리이며, 같은 Windows 계정의 파일을 직접 읽을 수 있는 사람에 대한 OS 격리를 제공하지 않습니다. 서로 신뢰하지 않는 사람은 별도 Windows 계정 또는 별도 컴퓨터를 사용하세요. 소유자 로그인용 `data/local-launch.json`도 공유하지 마세요.

AI는 소스 파일을 바탕으로 변경안을 생성합니다. 보안·설정·서버 진입점은 수정 대상에서 제외합니다. 원본이 바뀐 오래된 변경안은 적용을 거부하며 원본 파일을 사용자별 백업에 보관합니다. 공용 소스 적용은 로컬 운영자만 가능합니다. 검토 후 적용한 코드의 동작은 운영자가 확인해야 합니다. GitHub 반영은 별도 커밋으로 관리합니다.

## 일정 연결
기존 컴퓨터의 Teams·Classroom 예약 수집과 Notion 연동은 기존 브리지를 계속 사용합니다. 새 컴퓨터에 개인 학교 로그인, 일정, 예약 작업을 복사하지 않습니다. 새 사용자의 직접 서비스 연결에는 운영자가 등록한 Google/Microsoft/Notion OAuth 앱과 사용자의 동의가 필요합니다. 학교의 관리자 승인 제한은 그대로 적용됩니다.

## GitHub
Issues로 요청을 기록하고 브랜치에서 수정한 뒤 자동 테스트를 확인합니다. `node --test`는 계정 분리·일정 규칙·수신 권한·AI 변경안 제한을 검증합니다. 저장소에 `.env`, `data`, `runtime`, `dist`, 로그인 상태, 개인 일정은 올리지 않습니다. 저장소는 공개이며 검증을 마친 설치 파일만 릴리스 자산으로 게시합니다.

## 설치본 빌드
`scripts/Prepare-Runtime.ps1`로 공식 Node 24와 Codex Windows x64 실행 파일을 내려받습니다. 고정된 공식 배포의 SHA256을 확인하고 리소스·라이선스를 `runtime`에 준비합니다. `scripts/Build-Installer.ps1`을 실행하면 테스트 후 Inno Setup으로 단일 설치 파일을 만듭니다. 컴파일러 경로는 `-Compiler`로 지정할 수 있습니다. 결과와 SHA256은 `dist`에 저장됩니다. 배포 전 빈 폴더 설치와 개인 데이터 미포함을 확인하세요.
